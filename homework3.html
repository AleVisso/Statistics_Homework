Toy ECC Scheme (ElGamal Variant) Walkthrough

  • Key Roles: Private key \(k \in [1, 8]\) (let \(k=3\)). Public key \(P = k \cdot G = 3(1,5) = (5,9)\).
  • Message Encoding: Represent plaintext as a valid curve point \(M(2, 10)\).
  • Encryption Steps: Select ephemeral key \(r = 2\). Compute \(C_1 = r \cdot G = 2(1,5) = (2,10)\) and \(C_2 = M + r \cdot P = (2,10) + 2(5,9) = (1,12)\). Ciphertext is \(((2,10), (1,12))\).
  • Decryption Steps: Receiver computes \(M = C_2 - k \cdot C_1 = (1,12) - 3(2,10) = (2,10)\).

Caesar Cipher Implementation Walkthrough

  • Key Role: Shift integer \(s \in [0, 25]\) (let \(s=3\)).
  • Message Encoding: Plaintext string representing the message, e.g., "CRYPTO".
  • Encryption Steps: Shift each letter forward modulo 26: \(C_i = (P_i + 3) \bmod 26\). "CRYPTO" becomes "FUBSWR".
  • Decryption Steps: Shift characters backward modulo 26: \(P_i = (C_i - 3) \bmod 26\). Recovers "CRYPTO".

Effectiveness and Limitations Discussion

Effectiveness on Long Texts: Letter frequency distributions converge closely to theoretical English benchmarks (\(E \approx 12.7\%\), \(T \approx 9.1\%\)), yielding near 100% key recovery accuracy.

Attack Comparison: Toy ECC vs. Caesar Statistical Attack

The toy ECC attack is an algebraic brute-force search over a small discrete cyclic group (\(8\) candidate scalars), verifying point equality. Conversely, the Caesar statistical attack exploits linguistic redundancy and frequency structures in human natural language rather than brute-forcing numerical keys.

Infeasibility on Real secp256k1 ECC

A properly configured secp256k1 curve operates on a 256-bit key space (\(\approx 1.15 \times 10^{77}\)). Exhaustive search is physically impossible due to thermodynamic constraints (Landauer's principle), preserving the intractability of the Elliptic Curve Discrete Logarithm Problem (ECDLP).

Optional Analysis: Vulnerabilities from Toy Design vs. Field Size

The primary vulnerability in the toy scheme arises entirely from artificial parameter restriction (\(n=9\)), which reduces computational security to trivial enumeration. In contrast, real-world vulnerabilities in elliptic curve cryptography typically stem from implementation flaws (e.g., nonce reuse in ECDSA leading to private key leakage) rather than weakness in the underlying secp256k1 algebraic group structure.
